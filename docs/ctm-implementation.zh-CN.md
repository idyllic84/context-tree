# CTM实现

## 核心：`src/context_tree/ctm2/`

按[CTM概念模型](ctm-concept-model.zh-CN.md)实现的CTM；`src/context_tree/pilot/`把它作为本地页面运行，执行者是pi会话。
概念条目与模块的逐条对照、哪些已评估、怎样评估的，见[实现规划](ctm-implementation-plan.zh-CN.md)第2节。
代码只保留每个流程与说明的当前版本（外加最多一个正在评估的候选）；旧版本与没有采用的做法记在评估记录里，代码在版本历史中。

| 模块 | 职责 | 概念模型 |
|---|---|---|
| `store.py` | SQLite记忆：条目、边、事件；写入／发生／有效区间与替换／观测时间；来源；“截至某时”的查询 | 3.1、第4节 |
| `tree.py` | 存储之上的树视图（`StoreTree`）：结构修改经由存储留下事件；送达看到的工作现状 | 3.4 |
| `ref.py` | 指向与对象：消息怎样指向工作（接续、指代、点名、时间），点名了哪些对象 | 5.1第1步 |
| `candidates.py` | 按指向找候选：最近的工作、运行中的执行者、待决事项与展示条目、对象（含标识的拼写误差）、时间 | 5.1第2步 |
| `deliver.py` | 送达：每部分送到哪里、以什么方式（接着做、新建、旁问、调研、控制、先问、CTM自己记下）；没有合适的时看全部工作再判断一次 | 5.1第3步 |
| `remember.py` | 派发之后写记忆：约束、指导、决定、事实、行为指导、设定，各自挂在所属位置；替换一步逐条与最相近的现行条目比对 | 5.1第5步、3.5、3.6、第4节 |
| `writeback.py` | 执行者答复的写回：执行证据、一条简要进度、长内容存为文档；记忆用的“现行条目”收集 | 5.2第6条、3.4 |
| `context.py` | 新执行者的初始context（路径与子树、最近执行过的兄弟、最近的对话、引用的别处结论、不要再用的做法、文档与文件索引）；复用会话收到的增量；调研条目的context；按预算降分辨率 | 第2节、3.2、5.2 |
| `execution.py`、`control.py` | 执行者生命周期（第一次执行时新建、之后复用会话；查询用只读fork）；转送；控制层的停顿分类与完成检查；越界与无进展的升级 | 5.2 |
| `progress.py` | 执行者答复的简要进度总结（做了什么、改动、验证、未决、失败） | 3.4、5.2第6条 |
| `recall.py`、`query.py` | 凭记忆回答执行者与用户的查询（只给现行内容，标出被替换与被质疑的）；记忆答不了时派只读执行 | 5.2第5条、5.3 |
| `relay.py` | 转述：编号展示物（带所属任务）、待决事项 | 5.4 |
| `documents.py` | 文件版本、文档（种类、用途、版本、按章节更新、过时）、对象约束索引、行为指导文档 | 3.5、3.6 |
| `objectfiles.py` | CTM自己的`ctm.md`记录：何时写、替换时改写或删除、源码注释的提议与收回 | 3.5、1.1 |
| `planner.py` | 规划者：子任务作为提议；用户原话已授权的直接成为计划；批准 | 3.4 |
| `scope.py` | 约束的去向：同一要求出现在别的分支上时上移、提议为对象约束或全局偏好；新工作引用兄弟上也适用的约束 | 3.5 |
| `maintain_store.py` | 定期维护：改挂、合并、改名、补先后、修状态、约束上移、Goal归属与同层结构判断；记录改挂造成的继承变化并告知执行者 | 5.6、3.4 |
| `root.py` | 根层：人格、对用户的理解、整体目标、偏好与全局约束、常用环境 | 3.3 |
| `ui.py`、`views.py` | 界面修改的传播；由记忆生成的页面（任务元数据、交流记录、文档） | 5.5、1.2、3.7 |
| `lifecycle.py` | 状态事件与合法转换；依赖与门控；前置完成→可执行；推翻→待重核；完成时向上折叠 | 3.4、第4节 |
| `model.py` | 模型调用（经`common/llm.py`），记录每次调用的角色与用量 | — |
| `pipeline.py` | 主流程：用户消息（指向 → 候选 → 送达 → 派发 → 记忆 → 结构判断 → 转述）；执行者答复（证据、进度、控制层、状态、升级与作答、遗留事项）；定期维护 | 第5节 |

离线测试（模型调用都替换掉）：`tests/test_ctm2_*.py` 与 `tests/test_pilot*.py`；页面检查 `tests/browser_pilot_ui.py`（见[开发说明](development.md)）。

## 早期原型（已删除）

早期原型`src/context_tree/ctm/`用来跑通“理解—定位—写入—组装—派发—写回—维护”的闭环，已于2026-11-23随旧的包一起删除；
之后`ctm2`里的第一版消息流程（理解→定位→放置→写回）于2026-11-25删除。它们的做法、与概念模型的差距和留下的教训见[演进](evolution.zh-CN.md)。
