# 用户行为模式

> 用途：这是从历史协作中总结的用户习惯，作为[CTM概念模型](ctm-concept-model.zh-CN.md)中“对用户的理解”（3.3）的初始内容，
> 也用来判断哪些场景常见、寻找推演的反例。它来自session内的历史记录，不能直接当作无session场景的测试（见[目标与方法](goals-and-method.zh-CN.md)）。
>
> 数据：本地agent对话日志，415个session、15,031条真实用户消息，已排除工具结果、系统注入与fork镜像。
> 方法：先开放编码480条得到初版分类；再全量做一次LLM粗标注取得分布；最后增量抽样，每轮读一小批、只报告新发现，消息层连续两轮无新发现即停。
> 标注为LLM单次判断，未经人工校准；私有原文与标注在Git外，本文只给汇总和转述。

## 1. 原4类的问题

原来的查询调研、任务说明、行为指导、探讨4类，在开放编码中可单类归入的占73%，
混合占16%，无法归入的占11%。主要缺口有三点：

- **状态核验与纠偏是两大独立行为**，不是“查询”或“指导”的子集；
- **短控制消息**（“继续”“改吧”“先别push”）会改变授权和生命周期，需要单独处理；
- **用户回灌现场**（贴日志、报告自己的操作结果）的作用是刷新状态，并不是下达任务。

## 2. 消息层：9个主类（全量分布）

| 主类 | 占比 | 中位长度（字） | 与原4类关系 | 下一条是纠偏的比例 |
|---|---:|---:|---|---:|
| 交付执行 | 25.4% | 39 | ≈任务说明 | 16.7% |
| 求知解释 | 19.4% | 35 | ≈查询调研 | 12.3% |
| **状态与证据核验** | 17.4% | 31 | 新 | 14.3% |
| **纠偏修复** | 16.4% | 41 | 新（原“指导”的一部分） | **25.6%** |
| **流程控制** | 9.5% | 11 | 新（原“指导”的另一部分） | 15.1% |
| 方案共创 | 6.0% | 45 | ≈探讨 | **19.5%** |
| **现场回灌** | 4.3% | 108 | 新 | 14.8% |
| 上下文路由 | 1.2% | 58 | 新 | 14.0% |
| 认可收束 | 0.4% | 3 | 新 | — |

另有225条为自动或模板消息。混合诉求占13.9%，由次类表达。

增量抽样补出4个子型：
- **澄清应答／槽位补全**：逐项回答agent的澄清问题；
- **社交开启**：只是问候或重新接触，不是收束；
- **审查门控的条件执行**：先核实再实施，后续动作依赖审查结果；
- **暂停加回滚**：除了停止，还要撤销已发生的改动。

## 3. 正交标签：决定“怎么做、记多久、从哪取”

| 标签 | 取值 | 关键数据 |
|---|---|---|
| 动作边界 | 仅认知／范围授权／禁止或收紧／未定 | 求知、核验、共创90%以上是“仅认知”，不能当成修改授权；流程控制中28%是禁止 |
| 有效期 | 本次／任务期／长期 | 纠偏64%、流程控制55%、交付执行40%为任务期：这些约束必须持续到任务结束 |
| context来源 | 自足／近邻／远距／外部现场 | 近邻65–97%；求知、交付、核验约70%需要**外部现场**；远距只占9.7%，主要集中在交付、共创、核验 |

结论：大多数消息很短，依赖紧邻轮次和实时现场；“远距历史”需求量不大，但一旦需要，
多数是约束、旧决议、旧任务，代价很高。

## 4. 工作层：session内部的真正单位

增量读session片段时，新模式在8轮中一直在出现，说明session层的形态很多，
但它们归结为5类工作单位。这正是“按session组织太粗”的具体含义：

| 工作单位 | 典型模式 | context应保存什么 |
|---|---|---|
| 制品生命周期 | 围绕同一文档或代码多阶段演化；新旧实现共存到退役；用户手改形成新基线；跨文件规则需要逐处核对 | 制品当前基线、版本、阶段、已覆盖与未覆盖的落点 |
| 调查／验证循环 | 修复声明后复发需要重开调查；证据手段逐级升级；评估口径重建使旧结论失效；验证沿交付层级推进；发布后进入观察期 | 假设与证据台账，带时间窗口和“世代”；结论的适用口径与失效标记 |
| 约束与角色绑定 | 约束有作用域、相互覆盖、执行闸门；参考对象与修改对象容易混淆；标识符和统计单位要校准 | 生效约束集，含范围与期限；对象角色表（参考／修改／上游／下游） |
| 任务栈与悬置债务 | 主任务被观测问题阻塞，转修复支线后返回；后台长操作悬置；解释支线不能抵消交付欠账 | 未完成义务、在途操作、返回点 |
| 决策与沉淀 | 前提被纠正后方案重算；把探索经验提炼成操作协议；被放弃的方案留下负面结论 | 决策及其前提、被否方案和原因、可复用流程 |

## 5. 在CTM中怎样处理各类消息

| 主类 | 在CTM中是什么 | 处理要点 |
|---|---|---|
| 求知解释 | 查询 | 不建节点；记忆能答就直接答，否则只读执行；不改动 |
| 状态与证据核验 | 查询 | 查执行痕迹和观测记录，区分已验证、推断、未知；不自动修复 |
| 交付执行 | 任务（新建或接着已有任务） | 范围清楚即派发；路径上的约束与对象约束随合同带上；报告产物、验证与残留 |
| 方案共创 | 查询，或产出设计文档的任务 | 只讨论取舍时是查询；要形成方案文档时是任务；形成的选择记为决定 |
| 纠偏修复 | 对已有内容的否定与新约束 | 被否内容记为被否方案；新要求判定为任务约束或对象约束；受影响的进行中执行收到更新 |
| 流程控制 | 对待决事项、执行者的控制 | 批准绑定到带编号的待决事项；暂停、停止经控制层执行 |
| 现场回灌 | 材料与观测 | 长材料存为文档；结果连到在途执行或调查 |
| 上下文路由 | 定位 | 按对象、工作名或时间指称找回节点；排除最近但无关的工作 |
| 认可收束 | 对展示内容的认可 | 简短回应，不启动新动作 |

## 6. 作为“对用户的理解”的初始内容

1. **消息多短、依赖近邻**：多数消息很短，65–97%依赖紧邻轮次；在CTM中，这由对话最近一段和展示物承担。
2. **远距依赖少但代价高**：只有9.7%的消息依赖远距历史，主要是约束、旧决定、旧任务。这些必须写进树和对象约束，而不是留在对话里。
3. **纠偏会连锁**：纠偏后下一条仍是纠偏的比例为25.6%，方案共创后为19.5%。被否定的内容和受影响的产物要显式记下并交给执行者。
4. **范围常被收窄**：纠偏中约一半是范围错误。CTM写执行合同时范围要写准，拿不准时偏窄。
5. **授权依赖具体动作**：求知、核验、共创90%以上只是认知需求，不是修改授权；短授权（“好的”“继续”）只绑定明确提出的待决事项。
6. **约束多为任务期**：纠偏64%、流程控制55%、交付执行40%的约束要持续到任务结束。
7. **现场优先于历史**：求知、交付、核验约七成依赖外部现场；记忆保存“去哪读、上次读到什么、何时观测”，而不是现场内容本身。
8. **工作单位**（第4节）对应CTM中的结构：制品生命周期 → 文档与文件版本；调查与验证循环 → 查询记录与报告文档；约束与角色绑定 → 两种约束；
   任务栈与悬置 → 任务关系、待决事项与在途执行；决策与沉淀 → 决定与知识文档。

## 7. 局限

- LLM单次标注，未做人工校准；claude来源占62%；session层模式尚未饱和。
- 数据来自session内，用户在其中说话的方式与面对一个无session助手时不同；“没有会话上下文时用户怎样指明工作”需要另外研究（会话第一条消息、长时间间隔后的消息等）。
